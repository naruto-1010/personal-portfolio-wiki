P02 / 15 · 階段一：AI 協作 輔助開發，而非取代驗證

AI 協作入門：寫出清楚的五要素需求提示詞

生成式 AI（如 ChatGPT、Gemini）能產生 HTML／Tailwind 程式碼、解釋語法與協助除錯，但前提是你必須給出具體需求，並在產出後親自測試，且絕不可將密碼或 API 金鑰貼給 AI。

互動練習：勾選需求五要素，即時組合提示詞

        P04 / 15 · 階段二：HTML 基礎
        HyperText Markup Language
      


      

        HTML 核心觀念：標記語言、元素與屬性
      

      

        HTML（超文字標記語言）不是用來算數學邏輯的程式語言，而是用來組織網頁內容結構的「標記語言」。瀏覽器會讀取標籤指令，呈現出文字、圖片與連結。
      


      
      

        

          
點擊下方程式碼部位，查看 HTML 元素解剖說明：

          起始標籤 + 內容 + 結束標籤 = 完整元素
        


        

          
          
          
          >
          
          
        


        

          起始標籤與元素：使用角括弧 <a 開啟一個超連結元素，代表這個元件的起點。點擊上方不同色塊可切換檢視各部位意義。
        

      


      
      

        

          

            
巢狀元素：嚴格遵守「先開後關」

            
          

          
<p>我是熱愛設計的初學者，專長是 <strong>網頁排版</strong>。</p>

          

            正確：先開 <p> 再開 <strong>，結束時先關 </strong> 再關 </p>。
          

        


        

          
空元素（Empty Elements）

          
<img src="assets/images/avatar.png" alt="個人頭像" />

          

            少數標籤內部不需要包文字內容，也沒有結束標籤（如 <img>、<meta>）。所有設定皆透過起始標籤內的屬性完成，且多個屬性間需以半形空格分隔。

        P07 / 15 · 階段三：Tailwind CSS 基礎
        Utility-First · v3 Play CDN
      


      

        Tailwind CSS 理念與 v3 Play CDN 快速引入
      

      

        傳統 CSS 需要在 HTML 與 CSS 檔間來回切換且容易遇到「命名困難」；Tailwind CSS 採用 Utility-First（功能類別優先），讓你直接在 class 中組合單一用途的樣式類別。
      


      

        
        

          

            
            
            
          

          

          

        


        
        

          

            
Play CDN 引入語法（置於 </head> 前）

            
<script src="https://cdn.tailwindcss.com/3.4.17"></script>

            
    
              
  • 教學常寫簡潔入口 cdn.tailwindcss.com，實務亦可固定版號如 3.4.17。
    • 
              
  • 免安裝 Node.js / npm，適合初學者練習與快速原型製作。
    • 
              
  • 需保持網路連線；正式大型網站建議改採 Vite / PostCSS / Tailwind CLI 建置最佳化。
    • 
            

          


          

            為何 Tailwind 不等於內聯樣式（Inline Styles）？
            
1. 統一設計規範：使用一致的間距與字級尺度。

            
2. 支援狀態變體：原生 style="" 無法寫 hover:、focus:。

            
3. 支援響應式斷點：原生 style="" 無法寫 md:、lg:。

        P10 / 15 · 階段四：RWD 原理
        Viewport · Mobile First (min-width)
      


      

        RWD 響應式原理：Viewport 與 Mobile First 思維
      

      

        RWD 讓同一份 HTML 依螢幕寬度自動調整排版。要讓 RWD 在手機生效，必須具備兩大基石：正確的 viewport 標籤，以及由小到大的 Mobile First 寫法。
      


      

        
        

          

            
互動對照：有設 Viewport vs. 忘記設定

            

              
              
            

          


          

            

              
My Portfolio

              
探索創意，創造可能

              
文字大小適中，單欄排列清晰，不需要左右滑動或放大縮放即可閱讀。

            

          


          
<meta name="viewport" content="width=device-width, initial-scale=1.0" />

        


        
        

          

            
Mobile First（由小螢幕擴展到大螢幕）

            

              Tailwind CSS 採用 min-width 判斷：無前綴代表手機預設樣式；加上 md: 代表達到 768px 以上才套用。
            

            

              
class="grid-cols-1 md:grid-cols-2 lg:grid-cols-3"

              
→ 預設一欄 ｜ ≥768px 兩欄 ｜ ≥1024px 三欄

            

          


          

            

              
                

                  比較項目
                  固定寬度 (width: 1200px)
                  響應式 (w-full max-w-6xl)
                

              
              
                

                  裝置適應力
                  小螢幕易出現水平溢出
                  隨螢幕寬度自動縮放
                

                

                  排版彈性
                  維持固定排列
                  可切換單欄、雙欄或多欄
                

                

                  HTML 維護
                  常需額外處理多套版面
                  共用同一份 HTML 結構

        P13 / 15 · 階段五：上線部署
        GitHub Pages 靜態託管
      


      

        GitHub Pages 部署流程與檔案結構重點
      

      

        GitHub Pages 可免費將公開 Repository 中的 HTML、CSS、JavaScript 與圖片發布為 HTTPS 靜態網站（不執行 PHP／Python 後端或傳統資料庫）。
      


      

        
        

          
專案目錄結構（點擊項目看說明）

          

            
            
            
            
          

          

            index.html（必要核心檔案）：GitHub Pages 預設從部署來源的根目錄尋找 index.html 作為首頁。若缺漏或放錯子資料夾，開啟網址會出現 404 錯誤。而 about.html、projects.html 則為選擇性擴充頁面。
          

        


        
        

          

            
5 步驟完成 GitHub Pages 發布

            
    
              
  1. 登入 GitHub，點擊「+」→ New repository（例：my-portfolio），設為 Public（注意勿上傳密碼或私人憑證）。
    2. 
              
  2. 上傳已準備好的 index.html 與 assets/images/ 等檔案。
    3. 
              
  3. 進入 Repository 上方的 Settings → 左側選單 Pages。
    4. 
              
  4. 在 Build and deployment 設定：Source: Deploy from a branch、Branch: main、Folder: / (root)，點擊 Save。
    5. 
              
  5. 至 Actions 確認部署完成後，取得網址（如 使用者名稱.github.io/my-portfolio/）。
    6. 
            

          


          

            

              圖片路徑解析實驗（Project Site 常見 404 原因）
              

                
                
              

            

            

              寫法：src="assets/images/avatar.png" → 實際讀取：使用者名稱.github.io/my-portfolio/assets/images/avatar.png（正確！）
            

          

        

      

    


    
    

      

        P14 / 15 · 階段五：驗證與除錯
        常見問題排除 ＋ 互動檢查清單
      


      

        發布後驗證與常見問題除錯
      

      

        網站上線後，建議透過下方互動檢查清單逐項驗證，並熟悉四大常見部署異常的排除方式。
      


      

        
        

          

            

              1. 404 Not Found
              
確認根目錄存在 index.html、Pages 分支與 Folder 設定正確，且 Actions 已部署完成。

            

            

              2. 圖片無法顯示破圖
              
檢查圖檔是否已上傳、是否使用相對路徑，並注意 GitHub 檔名區分大小寫。

            

            

              3. 修改後網頁沒更新
              
確認有按下 Commit、Actions 已完成重新部署，並用無痕視窗排除快取。

            

            

              4. 導覽連結無法跳轉
              
檢查目標 .html 檔名拼字與大小寫是否與 href 完全一致。
